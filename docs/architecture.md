# Initial service architecture

A single Rust/Axum process owns command authorization, SQLite state, migrations, immutable strategy versions, data snapshots, sequential jobs and append events. React, the native Rust CLI and official Rust rmcp stdio bridge invoke the authenticated `/api/command` contract. Browser-local demo state is explicitly separate.

Pine runs in a separate Node 22 process using the existing PineTS 0.11.1 adapter. Bubblewrap exposes only read-only application runtime files and system libraries; environment and network are isolated. Jobs have bounded heap, wall time and response size. Sandbox creation failure fails the job. No broker credentials or database directory enter the worker. Server administrators install trusted dependencies; do not add secret files under worker-mounted source/dependency directories.

The first Composer strategy calculator is implemented in TypeScript and runs inside the same isolated Node worker contract, with Rust owning scheduling, storage and session commits. It implements real multi-asset weighted trees, return conditions, momentum ranking, bar-count/calendar/threshold rebalancing, fractional shares, sell-before-buy and fees. Decision uses a closed bar, execution the next bar open. Aligned complete symbol data is required. Warmup condition selects its no branch; filter warmup holds cash. Daily/weekly/monthly decisions occur at the first observed closed bar of a new period in the dataset timezone; a missing holiday bar is never invented. Report frames retain decisions, orders, cash, quantities and equity. Any replacement engine must pass the same numerical contract before substitution.

Closed-bar continuous simulation accepts append-only confirmed market events, either bound to a market subscription or explicitly imported. Each accepted event has a unique ID and immutable data snapshot. Only the visible prefix enters the engine; rebuilding that prefix restores deterministic native engine state. Previous committed historical frames must match or the event fails with a repaint diagnostic. Tick constructs are rejected for this execution mode. This mode never creates an external order from a native Pine backtest fill. Coinbase uses a default 120-second confirmation watermark; ordinary chart quotes and forming bars continue to update before confirmation.

A separate persistent Pine event host runs in a long-lived isolated Node process. Rust journals market events and fills before applying them, and reconstructs state from the immutable seed and event journal after restart. Same-bar updates restore committed state, while verified global primitive `varip` values survive rollback. Recorded execution time drives `timenow`, including recovery. Broker strategies require `calc_on_every_tick=true`; historical warmup computes variables against a flat account with order matching disabled. Subsequent strategy position and equity derive from actual Rust local-paper fills or authenticated external feedback, including partial fills and duplicate fill IDs. Local-paper hosts share the manual USD account; reference capital does not reserve cash. Pause disables order dispatch while calculation and fill reconciliation continue; stop cancels this host's unfilled local orders and retains existing positions.

The event host rejects live dependency datasets, scoped/composite `varip`, and `calc_on_order_fills` recursion until those semantics are implemented and verified. The default budget is two hosts, configurable from one to eight; worker interactions currently serialize through a process registry mutex. Each worker operation has a 10-second deadline plus memory/output/process limits. This is a single-instance local/server implementation, without a multi-tenant throughput claim. Public-script historical execution coverage is separate from tick, broker and TradingView numerical equivalence testing.

The service claims queued work atomically. Cancellation wins until terminal commit. On process restart queued work resumes; an interrupted running job is retained as interrupted with no successful result, requiring explicit new/retry command. A data-directory lock prevents competing writers, including on different ports. Result and terminal event commit together.

Plugins use `trading.plugin.v1` manifests, independent processes and explicit host permission checks. The initial host permits only `input.read`; filesystem writes, host file access, network and secret access are absent. Three loaded examples implement CSV parsing, moving average and equity reports. Extensions are installed locally by the administrator; no remote JS is injected.

Alpaca targets the Paper endpoint only. Client order IDs bind immutable requests; uncertain submissions remain unknown until query-by-client-ID reconciliation. The market data adapter returns provider/feed/adjustment details and refuses truncated pagination. Dedicated project credentials were not supplied, so real account/order/network acceptance is not claimed.

Official implementation references: [Axum 0.8.6](https://docs.rs/axum/0.8.6/axum/), [SQLx 0.8.6](https://docs.rs/sqlx/0.8.6/sqlx/), [rmcp 3.2.0](https://docs.rs/rmcp/3.2.0/rmcp/), [PineTS](https://github.com/LuxAlgo/PineTS).

The server stores the execution-adapter content hash in run manifests alongside strategy/data/input/config hashes. Queued work fails explicitly if the adapter changes or disappears, so a restart after an upgrade cannot silently recompute old work with a different implementation. Recorded successful results remain readable. Deployment includes a fixed Rust toolchain, Cargo.lock, pnpm-lock and pinned package manager; container API, React serving and sandboxed Pine native fills were independently exercised; see docs/acceptance/docker-runtime.json for the tested image hash and runtime evidence.
