1. Delivery modes

| Mode | First-use experience | Who pays for data? | What can realistically be promised? | Main tradeoff |
| A. Free public/replay | Open a URL and immediately chart, import Pine, backtest and paper-trade a labeled replay; optional live venue data only with appropriate distribution rights | Project owns/licences replay fixtures; zero paid live feed is possible if the demo stays offline/replay | A complete feature demonstration, repeatable and useful outside market hours. It cannot by itself promise current consolidated US tape, real night ticks or arbitrary current history | Least friction and cost; replay must be visibly distinguished from live data. Public API accessibility is not public redistribution permission |
| B. Self-hosted own data connection/BYOK | Install Tickgrove, choose provider, add dedicated credentials, test entitlements, then use live data | Each user/organization pays its own provider plan; local/public crypto feeds may have no subscription charge | With eligible paid SIP+BOATS access, strong US day/pre/post/night coverage; a chosen crypto exchange supplies its own live market. CLI/MCP operate within the user's contract | Better autonomy and open-base fit, but more onboarding and uneven data budgets. It is a candidate, not a decision already made |
| C. Project-funded shared licensed service | Open Tickgrove and immediately receive centrally managed authorized live data | Project pays data platform + feed rights + any per-user/device/display/non-display charges + hosting | Smoothest experience. A licensed derived composite can support broad live charts relatively cheaply; official consolidated tape/overnight/full tick export is a larger contracted product | Central uptime, access control, reporting, cost management, license boundaries and abuse/rate protection become project obligations |
| Hybrid proposal | Public no-key replay first; optional project-paid licensed chart feed; personal/organization connectors for required SIP/night/history/automation | Shared baseline by project; specialist subscriptions by the users who require them | Lets the software stay fully open and functional while choosing data quality/cost independently. No silent change from a baseline feed to a user's strategy feed | Some source choices remain, but keep them in one Data Connection setup and a compact chart source badge |

No-cost public launch should not be described as “Yahoo/Coinbase for everyone.” The current sources' internal/personal research status is not a shared deployment licence. A free-to-end-user experience can still require project-paid data, and a replay package must itself have redistribution rights or use clearly synthetic data.

4. Costs that must not be combined into one misleading number

Software/infrastructure: Tickgrove code licensing, machine/VM, storage, traffic, backups, monitoring and support. A private local installation needs no separately purchased SQLite server; existing hardware may avoid extra hosting spend. This research did not price a cloud deployment, so no arbitrary VM dollar amount is included.
Data acquisition: provider subscription, optional historical bulk usage, source/feed add-ons and archive limits.
Rights: individual/professional eligibility, exchange display users/devices, non-display strategy computation/automated execution, external distribution, raw tick/file/API export and derived works. Different uses can carry different terms/charges; a chart display licence is not a complete research/automation/data-export licence.
Operation: identity/tenant controls, user entitlement declarations where required, usage reporting, support and uptime. A low provider base price does not price these obligations.

Concrete budget envelopes, only where evidence allows:
- A replay-only public experience: $0 paid live-data subscription is possible; replay-content rights and hosting remain.
- B eligible personal US SIP+BOATS: Alpaca's published $99/month data plan + the user's infrastructure. This is one candidate, not a mandatory user purchase or universal eligibility promise.
- B deeper US history alternative: Massive Advanced $199 billed monthly or $1,920 upfront/year + infrastructure; night not covered by this verified matrix.
- C derived broad US chart experience: investigate Databento Standard/EQUS.MINI at $199/month + infra, confirm the intended shared display/export use under its current terms. This buys a composite source, not SIP; night and unrestricted downstream export are separate decisions.
- C Massive full live market: monthly base $2,499 + listed Full Market add-on $1,999 = $4,498/month in published platform/add-on fees before exchange/usage/user/non-display/export/taxes/infra. This is arithmetic on posted list prices, not an all-inclusive commercial quote. Base-only FMV is cheaper than full tape but has different semantics. Annual/committed base options change cash flow and obligations.
- C Alpaca shared SIP+night or Coinbase/Kraken shared crypto: suitable commercial quote/rights required; no defensible flat total established in this review.

5. Minimum viable combinations (our proposals, awaiting product/budget choice)

A. If zero project data budget is the priority: make no-key replay genuinely excellent; include chart/Pine/backtest/paper/alert examples with explicit replay time. Offer private user connections for live sources. This satisfies an easy feature trial, but is not the final live-market requirement.

B. If formal personal use is the priority: one polished Alpaca setup for entitled SIP+BOATS, plus a permitted crypto venue setup. Keep different feed/session/venue identities pinned to strategies. An optional Massive connection supports users needing its deeper historical archive. No need to require every user to subscribe to three vendors.

C. If “open link, see live general markets immediately” is the priority: a project-funded licensed data gateway is the natural model. Evaluate EQUS.MINI for stock/ETF chart display with an honest composite label; use explicit licensed crypto distribution. For official full tape or night trading semantics, cost/contract a separate SIP/BOATS tier. A desktop/self-hosted client consuming that gateway is still data redistribution, even though its code is open source.

Hybrid (recommended for discussion, not selected): ship the same open core with a first-run Replay choice, one simple Data Connection setup, and interchangeable local/provider or shared-gateway adapters. A project-funded licensed chart feed can be added later without changing the chart API. Serious strategies/backtests can bind to dedicated formal sources. This separates onboarding quality from the decision to subsidize everyone's data bill and avoids forcing an open project to become a full market-data reseller immediately.

Regardless of mode, keep one canonical capability/event contract. The server must distinguish actual trades, BBO, indicative/composite prices, corrected bars, delay and permitted uses; the UI may simplify these into compact source/session labels. Never silently join Mini live, SIP history, Yahoo price and BOATS night into one reproducible strategy series. Choosing a commercial model does not remove the P0 engineering fixes from the first report.
