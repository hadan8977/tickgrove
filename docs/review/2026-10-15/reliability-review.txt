PRIORITY ENGINEERING FINDINGS

R1 P1 — Unsupported relative/trailing Pine exits can become immediate market orders.
Evidence: server/src/pine_host.rs:551,593-604 dispatch reads only absolute limit/stop; absent both defaults to market. No profit/loss/trail_* validation. src/pine/host.ts:85 forwards native pending orders. Reproduced actual PineEventHost for strategy.exit('Exit','L',profit=20,loss=10) and strategy.exit('Exit','L',trail_points=2,trail_offset=1): both emit pending exit, category exit, qty 0, relevant relative/trailing fields, no limit/stop, no OCA name. Rust fills quantity from open trades and maps to market. This is stronger than the documented unsupported boundary: intended protective order becomes executable market exit. Probe executes actual intent generation; Rust mapping is source-verified, not an end-to-end real/local venue fill claim.
Fix first: reject every unsupported order field/category/type before dispatch; typed intent enum, explicit relative price conversion and OCO/trailing state machine only when supported. Same-ID order changes must compare full type/side/from_entry as well as price: current amendment at :606-608 changes qty/prices but preserves old local order type/side.
Gate: relative profit/loss, trailing, bracket, same-ID market→limit/stop, side reversal, partial fill/cancel cases each either exact expected ledger or explicit non-submitting failure. Never silently downgrade.

R2 P1 — External feedback validates quantity, but not direction against the issued order.
Evidence: src/pine/host.ts:85 checks issued order ID and max remaining quantity; src/pine/broker.ts:7-11 accepts either valid side and immediately projects it; server/src/pine_host.rs:193-233 forwards authorized fill. Reproduced issued L direction=1 qty=2; feedback side=sell qty=2 accepted, positionSize=-2. Fixture starting cash1000/price10 becomes cash1020/equity1000, rather than rejecting contradictory broker feedback.
Impact: adapter errors can invert strategy position without reconciliation failure; scope authorization alone does not validate execution identity.
Fix: match immutable issued-intent side, strategy/session, broker order ID, cumulative quantity, allowed fill time/order state; explicit reject/cancel/status events. Account snapshot reconciliation after restart.
Gate: opposite side, stale/unissued order, future/out-of-order fill, overfill, repeated same ID/different payload fail without ledger mutation; valid partials and signed reversal reconcile exactly.

R3 P1 — Realtime Pine host alerts are not in durable alert history.
Evidence: scripts/pine-host-worker.cjs:10-12 returns alerts; server/src/pine_host.rs:502-514 stores only latest result; no pine_alert_history write in that module. Only worker.rs:214-230 writes this table for closed-bar paper jobs; alerts.rs:62-68 reads that table.
Actual isolated Rust fixture: indicator alert('probe-live-alert',alert.freq_all), liveHostAlertCount=1; alerts.strategyHistory=[] before restart AND after restart. Result file records this observed failure.
Impact: Alerts panel/history does not receive real-time script alerts; latest status can overwrite the only convenient observation, even though input journal permits future recomputation.
Fix: durable normalized alert event table with immutable strategy/input/context version and source event ID; commit trigger alongside event cursor/result; unified history API; distinct occurrence versus notification delivery state/outbox.
Gate: one/all/per-bar/per-close frequencies, close browser, restart after trigger, duplicate ticks, source correction and delivery retry preserve expected events without duplicate notifications.

R4 P1 — Quote alerts have an unrecovered crash window after source persistence.
Source evidence: server/src/market/mod.rs:104 commits quote INSERT, then account::on_quote at :123, then alerts::on_quote at :135; alerts transaction starts alerts.rs:96. No durable alert-consumer cursor/replay path on startup (lib.rs:119-122 starts market, paper, host only).
Impact: crash/database error after quote commit but before alert commit loses a transient cross; next quote might no longer meet threshold. Restart can also compare against stale previous_price. This is source-verified architectural failure window; no forced-crash empirical reproduction performed in this review.
Fix: consume persisted quotes using per-consumer cursor committed atomically with alert state/history. Separate trigger truth from retries of downstream notification; explicit stale/outage policy and gap status.
Gate: fault injection at quote inserted / alert insert / cursor advance boundaries; restart exactly preserves deterministic trigger set. Price went 99→101→99 with crash between insert and evaluation must not silently disappear.

R5 P1 — Host event cursor advances before durable order intent creation.
Source evidence: server/src/pine_host.rs:503 journals market, :507-514 commits result+cursor, :518 calls dispatch; dispatch first persists intent only at :612. Crash in between leaves a committed processed cursor without corresponding durable dispatch intent. Replay at :433-448 recomputes worker state but does not dispatch already-processed source events. A later event may happen to re-emit intent, but that is not a recovery guarantee, especially if later script cancels/replaces it.
Fix: commit result/cursor and a complete immutable outbox of desired actions in one transaction; dedicated idempotent dispatcher drains outbox after restart; acknowledge external/local outcomes transactionally.
Gate: kill at every journal/result/outbox/submission/response/commit boundary, reconnect, compare exact intended order set and actual ledger. No lost or duplicated intent. Source-verified finding; fault injection still needed.
