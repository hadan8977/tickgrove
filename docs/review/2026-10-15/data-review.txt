Tickgrove formal market-data review
Date: 2026-10-15 UTC
Reviewed SHA: ec039649fe9f4b8729b977e819509910bf95cc2a
Verdict: ISSUES
Method: Independent source inspection of Rust market/history/stream/calendar/account/paper and React feed code; comparison against official vendor documentation retrieved 2026-10-15. Read repository AGENTS.md and docs/review/data-and-storage-2026-10-14.md. No source changes, no live credential/entitlement tests, no account or paper state writes, no load test. No additional SKILL.md used. Findings below are source-demonstrable unless explicitly marked a design recommendation or external entitlement gap. Prior real-stream acceptance is historical evidence, not this review's execution.
Assumption: BYOK-first personal self-hosting; optional explicitly labeled replay/free experience. A hosted public data product is a separate entitlement/deployment profile. User business model remains undecided.

Conclusion
The current adapters prove a useful research prototype, not formal data parity. Coverage is dynamic, not a hardcoded handful of symbols, but provider coverage, connection budget, feed semantics and resilience prevent a professional multi-chart claim. The largest next step is a shared Rust data plane with provider/account/feed connection managers, capability contracts and replayable typed events. Adding another chart or changing 700 ms polling to WS alone will not solve this.

Release blockers and prioritized findings

D01 — P0: Alpaca multi-chart connections violate common provider connection limits.
Evidence: server/src/market/mod.rs:387 deduplicates only the exact provider/symbol/timeframe/feed/session tuple; :403 spawns a separate stream per such subscription. server/src/market/stream.rs:545-575 opens a socket for one symbol; Coinbase :286 likewise uses a one-symbol subscription. Default max_subscriptions=32 is an app budget, not a vendor entitlement. Alpaca official WS documentation says many plans allow only one connection per endpoint and a second returns 406.
Reproduction specification: With a one-connection account, subscribe AAPL 1m, AAPL 1H and MSFT 1m. Current code attempts three sockets to the same feed. No credential test was performed; the socket ownership path is explicit in source.
Improvement: ProviderSession keyed by credential profile + environment + feed endpoint, one upstream symbol subscription with reference-counted consumers, local timeframe aggregation. A chart closing releases only its reference; account/alert/strategy consumers keep the source alive. Track requested versus acknowledged symbols and plan limits. Do not open a new upstream socket for another timeframe/browser.
Acceptance: Mock provider enforcing one socket sees one socket for 30 symbols × 3 timeframes; equivalent requests issue no duplicate subscribe; removing one consumer leaves others; reconnect atomically restores intended subscriptions; configured symbol exhaustion is an actionable state, not reconnect churn. Repeat with dedicated real IEX/SIP credentials before claiming those feeds verified.
Official: https://docs.alpaca.markets/us/docs/streaming-market-data ; https://docs.alpaca.markets/us/docs/about-market-data-api

D02 — P0: Night feed endpoints and regular/extended session contracts are incorrect or incomplete.
Evidence: stream.rs:562 constructs wss://stream.data.alpaca.markets/v2/{feed} for all four feeds. Official BOATS/overnight uses v1beta1. history.rs:286 accepts overnight and :323 passes it unchanged; official overnight historical requests use boats, with delayed end-time restrictions for the free plan. history.rs:82-85 and market/mod.rs:378-383 reject Alpaca extended sessions. Alpaca identity defaults regular except overnight (market/mod.rs:80). period.rs:109-156 expected_base_times has no overnight branch; bounds at :20-51 treats every >=1D timeframe, including 1W, as one overnight session. Thus a night weekly bar is not a week.
Additional direct defect: history.rs:359-373 assigns intraday non-night closeTime through calendar::bar_close. calendar.rs:102-113 always clamps to regular close without session filtering. An Alpaca 17:00 ET bar receives 16:00 ET closeTime; validate_data at commands.rs:324-327 rejects it. Premarket bars are not filtered out there either. This source-derived case needs an adapter fixture, not production credentials.
Improvement: One explicit FeedContract mapping live endpoint, historical endpoint/feed, supported data kinds, delay/indicative policy and session capability. Session calendar becomes venue/feed/session aware. Normalize provider bars with precise regular/extended/overnight membership; derive requested intervals from canonical bars where provider anchoring differs. Support daily/weekly/night boundaries intentionally, not by seconds alone.
Acceptance: Feed-matrix URL/request tests; permitted/rejected entitlement windows; actual 04:00, 09:30, 16:00, 20:00 boundaries, Sunday night, holiday preceding night, early close, DST and cross-year weeks; no bar with closeTime<=time; compare pre/post and overnight known fixtures. Without a real entitled account retain “adapter tested / live unverified”.
Official: https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data ; https://docs.alpaca.markets/us/docs/245-trading-for-trading-api

D03 — P0: Indicative/unknown quotes are not positively excluded from local execution.
Evidence: market/mod.rs:80 marks all Alpaca delay.kind as unknown. :119-122 permits quote-driven local account execution for USD, non-Yahoo, delay != delayed. account.rs:116 replays a cached quote into on_quote based only on connected status; :258-262 checks age/future time, not indicative/executable entitlement. Once D02 makes overnight connect, its real-time indicative quote can satisfy this gate. This is a latent semantic defect, not evidence that any live order was executed.
Improvement: Separate entitlement, coverage, event kind, freshness, indicative status and execution eligibility. Explicitly decide whether local simulation accepts IEX venue prices, SIP NBBO or BOATS quotes; label that model. Unknown/indicative/delayed is view-only by default. Feed policy must be enforced centrally both for cached and new quotes, API/CLI/MCP and UI. Broker fills remain the execution truth; data quotes do not prove broker fill availability.
Acceptance: A same-timestamp quote matrix (SIP, IEX, BOATS, indicative overnight, unknown, delayed, halted, crossed, stale, future) drives expected view/alert/simulation permissions. Indicative never fills local orders; no direct API bypass. UI makes IEX single-venue versus SIP coverage intelligible without exposing implementation detail.
Official feed distinctions: https://docs.alpaca.markets/us/docs/245-trading-for-trading-api

D04 — P0 for advertised tick-based strategies: Alpaca corrections/cancels/halt state silently disappear.
Evidence: stream.rs:575 handles only q/t/b/u; default branch discards other messages. Official c trade corrections and x cancel/errors are automatically delivered on trade subscription. Status/LULD are also not subscribed/handled. alpaca_wire.rs:17-32 preserves conditions/raw source for q/t, which is useful, but there is no typed revision ledger for these event kinds.
Improvement: Canonical MarketEvent includes TradeCorrection, TradeCancel, TradingStatus, LULD, BarRevision and SourceGap with original/corrected IDs, source timestamp and receipt timestamp. Dedup scope includes venue/feed/instrument, not a globally assumed trade ID. Correct derived views/bars; never rewrite committed trading history silently. Define freeze/recompute policy for strategies with accepted source revisions, and expose reason.
Acceptance: Inject trade → duplicate → correction → cancel → halt → resume and verify one auditable lineage, corrected chart/volume, no double fill/alert, explicit strategy state. Replaying the same persisted sequence yields identical derived state. Official minute updatedBars are retained as reconciliation, not a substitute for a missing trade-revision contract.
Official: https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data

D05 — P0 before a public hosted launch: code openness is not data redistribution permission.
Evidence: existing public-provider paths are Yahoo and Coinbase, while the software can expose their data through HTTP/CLI/MCP and charts. Coinbase terms dated 2026-08-07 limit internal/personal/research use and third-party distribution including derived charts absent prior consent. Massive individual terms similarly differ from its business contract. Existing report already identifies Yahoo licensing uncertainty. This review does not establish clearance for any public preview.
Improvement: Ship three explicit profiles: (1) Replay: fixtures with verified redistribution rights or clearly synthetic educational data, source/time label, deterministic offline first-run; (2) Personal BYOK: users configure their dedicated provider, rights stay with their subscription; (3) Hosted: only contracted display/distribution sources and entitlement controls. In hosted mode also control machine-readable data export through CLI/MCP/API: a display license does not necessarily allow offering a downstream data feed. Do not silently publish production snapshots as sample fixtures.
Acceptance: A deployment manifest states intended use, source, permitted display/export modes and license evidence; a no-key install has a useful honest replay path; a hosted demo cannot select a personal-only provider without explicit permitted profile. No claim that BYOK alone clears every multi-user scenario.
Official: https://www.coinbase.com/legal/market_data ; https://www.massive.com/legal/market-data-terms-of-service ; https://massive.com/legal/businesses-terms-of-service

D06 — P1: Last trade and quote midpoint are mixed into a single display price.
Evidence: alpaca_wire.rs:22 sets quote.price=(bid+ask)/2. React src/data/feed.ts:472-478 overwrites the same prices[symbol] for quote or trade. A quote can therefore move “last price” without a trade. stream.rs provisional_quote also derives OHLC from quote marks; the metadata does disclose provisional/volume unknown, which should remain.
Improvement: Typed LastTrade, Bid, Ask, Mid, PreviousSessionClose; each has its own timestamps/quality. Chart chooses trade-based or explicitly quote-based series. Regular close, extended last and overnight last must be separate display fields with clear active-session selection. Do not compare one vendor midpoint with another vendor last trade and call it a data error.
Acceptance: A pure quote update moves bid/ask/mid only; last trade changes only on eligible trade; session price and daily change have golden tests. Existing quote-only fallback can show “indicative quote” without masquerading as an executed last price.

D07 — P1: Reconnection recovers some bars, not a complete tick stream; Alpaca has no matching history-repair loop.
Evidence: stream.rs:7-8 starts Yahoo and Coinbase reconcile loops only. Coinbase repair :125-156 requests five recent candles; restore_builder :159-193 replays only already persisted trades. Missing trades flagged by heartbeat :308 are not fetched from the trades endpoint. This is honest incomplete-state behavior but cannot support a no-loss tick claim. Coinbase official matches channel may drop messages and recommends fetching missing trades via REST.
Improvement: Durable source checkpoints/sequence coverage; subscribe-and-buffer then history/backfill to a bounded cutoff, dedup overlap and switch to live; distinguish recovered bars from recovered trades. Provider-specific bounded trade repair where available, otherwise durable Gap marker and strategy pause/fresh warmup. Alpaca needs historical bar/trade repair with feed-matched adjustments and entitlements. Avoid promising restoration of never-received ticks from OHLC.
Acceptance: Disconnect across candle close and process restart; duplicate/out-of-order delivery; 10-second and 15-minute gap; history unavailable/expired. Each range ends as complete, repaired-with-provenance or explicit unresolved gap. Cursor expiry never silently resumes a tick-sensitive strategy. Deterministic journal replay covers received events only.
Official: https://docs.cdp.coinbase.com/exchange/websocket-feed/channels

D08 — P1: Missing/no-trade/illiquid intervals are conflated.
Evidence: Coinbase history.rs:163-166 marks every missing time slot as a gap; state.rs:67-68 labels Missing/no-trade buckets together. Alpaca official_minute at stream.rs:533-535 demands contiguous minute bars. Official providers can omit buckets with no eligible trades. Blanket rejection makes general thin symbols difficult, while blindly forward-filling would create false liquidity.
Improvement: Distinguish NoEligibleTrades, ClosedSession, TransportGap, ProviderUnavailable, PendingCorrection. Keep raw bars sparse; if a chart/strategy needs a continuous calendar series, use an explicit derived-series policy with zero volume, synthetic marker and documented execution restrictions. Do not treat verified inactivity as packet loss.
Acceptance: Thinly traded ETF/no-trade minute, halt, provider missing response and true dropped sequence cases yield distinct statuses; no artificial executable price or invented volume; a strategy’s gap policy is fixed in its manifest.
Official: https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles ; https://massive.com/knowledge-base/article/does-massive-offer-pre-market-and-after-hours-data

D09 — P1: Rate control and history caching are not provider-wide.
Evidence: market/mod.rs:24-25 has a concurrency semaphore(4), history.rs:154 sleeps 120 ms per page, but instruments.rs:2-5 and :23-27, market/mod.rs:185-188/:207-213/:268-274/:288-294 use independent client requests. history.rs:24-29 treats all non-2xx as generic failures with no Retry-After/retry category. Every client() call constructs a new HTTP client at market/mod.rs:83-87. History persistence at history.rs:471-479 stores a new complete payload/UUID even for repeated requests.
Improvement: Shared reqwest clients/connection pools, provider/account/IP token buckets, request coalescing and interval cache; bounded jittered retries honoring Retry-After for 429/temporary errors, fast actionable failure for auth/entitlement errors; reference catalog cached and refreshed. Keep data license cache retention restrictions in the profile.
Acceptance: Concurrent search/history/depth/reconcile workload stays within configured budget; 429 preserves work and retries boundedly; invalid credentials do not loop every three seconds forever; ten identical history requests issue one request and share an immutable content object. Coinbase's current public documented budget is 10 requests/s/IP and bursts to 15; plan-derived limits are configuration, not universal constants.
Official: https://docs.cdp.coinbase.com/exchange/rest-api/rate-limits

D10 — P1: Synchronous per-event database work and per-subscription browser polling limit honest realtime performance.
Evidence: lib.rs:100-102 uses one SQLite pool connection. market/mod.rs:104-145 inserts event, updates subscription, looks up identity then executes account/alerts inline. Coinbase socket :309 awaits multiple DB writes on every trade before reading the next socket message. React feed.ts:111-113 schedules every 700 ms; :517-545 polls subscriptions in batches of four and waits for each batch. A 700 ms timer is not a measured end-to-end latency guarantee.
Improvement: Keep SQLite for single-user self-hosting, but isolate socket read/parse from durable append via bounded queues and one ordered writer with microbatch transactions; cache immutable identity/latest quote. Quote coalescing is allowed only for UI delivery, not silently in strategy/audit ingestion. Browser gets one multiplexed resumable SSE/WS stream with cursor+snapshot recovery. Add queue depth, ingest lag, event/receive timestamps, reconnect reasons and drop/gap counters. A full queue must backpressure or record a gap/freeze; never silently lose a trade.
Acceptance proposal (targets, not measured capability): declare reference hardware and subscription profile; benchmark 50 symbols/6 charts/3 timeframes with 2,000 events/s sustained and a 10,000 events/s 60-second burst. Initially target provider-frame receipt to durable dispatch p95<250 ms, p99<1 s, no unaccounted received-event loss; browser receipt-to-paint p95<100 ms. Adjust only from measured evidence and publish limitations. Test authorized real feeds for at least 5 trading days plus overnight and crypto weekend before claiming durable real-time readiness.

D11 — P1: Retention and reproducibility need storage tiering and lifecycle controls.
Evidence: market/mod.rs:151-167 prunes the global event cursor by count, affecting all subscriptions; stream.rs:119 prunes closed bars, :538-541 keeps about 35 days of source bars. No general snapshot/job/host-journal cleanup was found. paper.rs:257 appends a bar to the full data array and :280-287 saves another complete snapshot each step: persistent history can grow quadratically before the 20,000-bar cap (commands.rs:298-300). This is not bounded long-running strategy storage.
Improvement: Separate operational state, recent event journal and immutable history objects. SQLite transactions remain authoritative locally; history/reports go to content-addressed chunked Parquet/DBN/local object storage with manifests, reference counts/pinning, quotas and archive policy. Capture provenance (provider/venue/feed/session/adjustment/schema/calendar version, request/receive times, hash), then compact only outside active consumers’ replay windows. Store incremental append segments plus periodic checkpoints, not every growing full array. Postgres is a later multi-user/multi-instance need, not a prerequisite for one good self-hosted release.
Acceptance: 7-day simulated continuous-run growth budget, quota pressure behavior, retention crossing an active strategy cursor, backup/restore of pinned strategy inputs and archive objects, hash/manifest validation, and recovery from object written but DB commit failed. No orphan cleanup may delete still-referenced backtest data.

D12 — P1 for research parity: instrument and corporate-action identity is current-only, not a point-in-time research universe.
Evidence: market/mod.rs:207-209 requests only active Alpaca assets; instruments.rs:82-89 derives identity from current exchange/symbol/class and only tradable/fractionable. It does not store the provider asset UUID, symbol-validity intervals, overnight_tradable/halted or corporate-action history. History supports adjustments, but a flag alone does not encode the revision/as-of definition of a research universe.
Improvement: Provider-independent instrument ID plus provider mappings valid from/to; stable asset IDs, delisted securities and symbol changes, corporate-action version/as-of, raw and adjusted series both traceable. Treat overnight eligibility and halted state as refreshed capabilities. Do not imply survivorship-free broad-market backtests from active symbol search.
Acceptance: Rename/delist/split/dividend fixtures preserve identity and reproducible series; a dated universe can include historical delisted assets; active UI lookup remains simple. This need not add screening/news features.

Fallback rules
- On primary feed failure show stale/disconnected immediately and preserve its identity. A preconfigured fallback may power a separately identified chart view after user-visible source change.
- A strategy remains pinned to source/feed/session/adjustment and should pause or explicitly redeploy to a new manifest; do not silently continue a SIP strategy on IEX, Yahoo, an indicative composite or another crypto venue.
- For first-run no-credential experience use explicit replay plus publicly accessible personal-use providers only where the actual deployment permits them. “Free live US whole market” is not a credible default promise.
- A large arbitrary symbol directory does not mean simultaneously streaming all symbols. Define coverage separately from active subscription capacity and show actual remaining provider budget only in connection settings.

Three architecture decisions to adopt
1. Data-first modular monolith in Rust: ProviderManager → typed immutable EventEnvelope → durable ingest/reconciliation → bar/reference stores → chart/alert/strategy consumers. One session per provider/account/feed, no transport ownership in chart subscriptions. Existing React UI talks to one resumable stream/API. A plugin connector must implement capabilities, normalization, checkpoints and fault semantics, not just return prices.
2. BYOK and hosted-data contracts are separate deployment profiles. Feed capabilities include actual/indicative, venue coverage, freshness policy, supported sessions/data kinds, allowed uses, connection/symbol/request limits and verification state. Public claims derive from tested capabilities; unknown is visible and non-executable by default.
3. SQLite remains operational storage for the first self-hosted release, with bounded journal + content-addressed historical objects and explicit replay/retention. Upgrade to Postgres for tenant isolation/multiple writers/HA only when those are product requirements or measured bottlenecks; Parquet/DBN handles large history, not another unbounded SQLite JSON column.

Latency and reliability contract
Measure separately: source timestamp→server received (includes vendor policy/network/clock error); server received→durable/dispatch (our controllable ingestion); dispatch→browser receipt→paint (network/browser); latest event age and known provider delay; last heartbeat age and unresolved sequence gaps. Delayed data can be promptly transported and still be delayed. Quote inactivity on an illiquid symbol is not by itself a connection failure. Exact exchange end-to-end latency cannot be asserted without synchronized clocks and reliable source timestamps. Preserve nanosecond source times where supplied and a monotonic internal sequence; UI may render milliseconds.
Suggested engineering SLOs in D10 are acceptance targets, not observed guarantees. Availability/SLA belongs to the chosen paid provider contract plus measured app operation. No-loss promise applies only to received, durably committed events within retention; never-received outage ticks need provider replay and may remain unrecoverable.

Phased implementation and hard gates
Phase A, before promotion: fix D01-D05 and D06; hide unsupported source/session choices behind clear capability state; fixture-driven protocol tests and six-chart integration from one provider session. No license purchase is needed to implement/fault-test these. Deliver a short onboarding: choose Replay or Connect source, test connection, choose instrument, see truthful source/session state.
Phase B, formal data beta: provider-wide limiter/cache; canonical events/corrections; source gap repair, resumable frontend stream, typed market prices, observability. Require real dedicated Alpaca entitlement validation across regular/pre/post/night and Coinbase live reconciliation; missing credentials remain an explicit external acceptance blocker, not “complete”.
Phase C, release candidate: incremental history/retention/recovery, corporate-action fixtures, replay parity, specified burst/soak test, distribution decision for public demo. Add Massive or Databento after the capability contract is proven; avoid implementing three vendors simultaneously before one feed works reliably.
Promotion gate: no P0 data findings, actual source/plan/session verification matrix, all charts share stable latest-price semantics, six-chart workload meets declared latency target, gap/correction/restart tests pass, repeatable backup restore, meaningful no-key demo and first-run flow, and the hosted demo's display/export permissions documented. Publish the constraints along with acceptance evidence; do not market “TradingView replacement”, “all-market free real-time” or “lossless tick engine” while these remain open.
