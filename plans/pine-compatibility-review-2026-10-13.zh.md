# Pine 兼容实现与验证

当前实现采用 PineTS 0.11.1，并修复应用接入层及方法命名参数绑定问题。已形成源码输入、离线数据、编译执行、原生回测、图表、历史账本回放和 CLI 的可运行链路。它为 Rust 系统提供一个可替换的执行组件；完整系统的服务、持久化与持续模拟仍按 [总体计划](trading-system-research-and-plan-2026-10-13.zh.md) 实施。

## 主要修改

原应用把 Pine 已成交记录转换成信号，再送入另一个回测器，造成第二次撮合。当前报告直接使用 PineTS 的成交数量、价格、费用、权益和未平仓仓位，展示用标记落在实际成交 K 线上。历史结束时仍持仓的交易保留为未平仓，不被强制结算。

参数由引擎的 AST 元数据解析，变量名用于区分同名标题。参数值独立保存，不通过文本替换改写 Pine。针对 UDT 方法的命名参数和默认参数，兼容层解析编译后函数的 AST，将参数按签名绑定，并保留序列历史；未知或重复参数报错。补丁限定于完整基础类型签名，升级 PineTS 时须复核是否移除。

浏览器使用可取消的独立 Worker，CLI 使用受时间和 V8 堆限制的 Worker。数据提供者只使用显式传入的数据，拒绝缺失标的和低周期数据。UTC 聚合与真实交易所会话数据分别处理，真实市场不能套用合成行情的聚合假设。

Pine 模拟入口现为独立历史账本回放。原先“把历史最后一笔成交变成当前买卖”的路径已移除。回放不会改变共享 demo 账户；持续模拟必须等待具备状态反馈和幂等保障的订单接口。

## 测试覆盖

43 项断言测试通过，涵盖以下方面。`npm test` 可复跑；`npm run typecheck` 和 `npm run build` 通过。

| 范围 | 验证内容 |
|---|---|
| 语言和状态 | v5／v6、数组、映射、矩阵、UDT、循环、持久变量、历史引用、元组、switch、na／nz、数学与字符串 |
| 参数 | 多行、命名参数、类型、同名标题、转义、范围、非法值；方法默认值、false／0、参数顺序、序列历史和错误诊断 |
| 原生策略账本 | 下一根开盘与当根收盘成交、数量、手续费、多空、部分平仓、撤单、未平仓盈亏、回放最终权益 |
| 数据请求 | 指定跨标的数据；高周期收盘前不可见；显式 lookahead_on；低周期子数组的数量与求和，包括最后一根；缺数据、坏时间戳、月线 closeTime、交易所会话聚合拒绝 |
| 绘图输出 | 表格与标签文字、填色几何、蜡烛体、形状位置和背景宽度；画布调用断言不等于像素对照 |
| 执行边界 | 循环上限、库导入错误、CLI 原生报告、退出码和输入文件错误 |

公开语料固定为 [pineforge-corpus](https://github.com/pineforge-4pass/pineforge-corpus) 的 312 个未修改 Pine 源文件，保留 Apache-2.0 许可、NOTICE、提交链接及 SHA-256。逐项结果见 [执行报告](research/pine-public-execution.json)，复跑命令为 `npm run test:pine-public`。

最终执行结果为 312／312 通过且权益有限，225 个产生已平仓交易。1 个案例提示 `plot.style_cross` 使用折线降级；该警告保留在报告中。报告内四个适配器文件的 SHA-256 与当前实现一致。补丁前的固定数据复跑为 311／312，唯一失败为方法命名参数绑定，保留在 [补丁前报告](research/pine-public-before-method-fix.json)。

语料包含 73 个技术指标案例、53 个复合策略、48 个订单案例、28 个 UDT 案例、19 个多周期案例、17 个 bracket 案例，以及矩阵、绘图、风控、会话等案例。每个脚本用独立 Worker 运行；同一轮使用固定的适配器代码快照。请求类脚本使用 15 分钟合成主序列，其余使用 60 分钟序列，并提供一致的 1 分钟子序列。

每例 256 根主 K 线属于执行冒烟测试。报告分别保留执行成功、有限权益、警告、交易笔数和用时；没有成交的脚本不能算作其订单分支已验证。逐脚本成功率也不能代表 TradingView 等价率。

## 浏览器与 CLI 验证

公开策略 Anvil Percent Costs 已通过浏览器命令接口完成回测和 900 根历史账本回放，最终权益一致，没有生成共享 demo 账户订单。生产构建另验证了带默认值和命名参数的方法：预期 13 单位，交易表显示 13 单位；页面错误记录为空。记录见 [浏览器冒烟结果](research/pine-browser-smoke.json)。

CLI 使用同一个执行适配器。仓库提供 [确定性合成数据](../examples/pine/synthetic-spy.json) 和 [运行说明](../README.md)，不依赖行情账户或 TradingView 登录。

## 尚未满足的兼容条件

1. 库 `import` 仍明确报错。下一步是带版本和内容哈希的本地库包解析、导出符号与命名空间解析；不能用源码正则拼接冒充库系统。
2. TradingView 同源数据逐值、逐笔对照尚未完成。需统一源码、输入、数据快照、时区、复权和撮合设置，再分别对比计算、订单意图、成交和权益。
3. 复杂绘图仍有样式、缩放、布局和重叠顺序差异；运行成功不能推导图表一致。
4. 持续模式的 `varip`、实时回滚、多次重算、重启恢复及外部成交反馈，须单独通过状态机测试。当前账本回放不能代替该验收。
5. 美股真实会话、DST、拆股分红、停牌和数据缺口，需要真实数据及日历适配器的合同测试。合成数据覆盖语言与调用链，不证明真实市场数据正确。
6. Worker 的时间和堆限制不是完整服务器安全隔离。Rust 任务宿主还需进程隔离、权限、持久化、取消和事件协议。

## 后续顺序

先建立 TradingView 对照样本与本地库解析，优先解决会产生静默错误的语义差异；随后为 Rust 服务固定策略版本、数据快照和运行协议。持续模拟通过订单状态及恢复测试后，再接入独立券商 Paper 账户。CLI、MCP 和 Web 共用服务端命令，不增加内置 AI 聊天。
